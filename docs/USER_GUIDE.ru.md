# Renamorph

Нативная утилита строки меню macOS: изменение расширения наблюдаемого файла означает запрос на локальное преобразование. Исходный формат определяется по содержимому, структуре контейнера и полному декодированию/разбору. Перед конвертацией сохраняется оригинал; Undo возвращает его байты из резерва.

Независимая реализация. История проекта и совместимость с прежним профилем описаны в [ORIGINS.md](ORIGINS.md).

## Запуск и сборка

Готовое локальное приложение: `dist/Renamorph.app`. Двойной щелчок в Finder или:

```bash
open dist/Renamorph.app
```

Собрать на этом Mac:

```bash
brew install pkgconf x264 lame opus libvorbis libvpx webp dav1d
./scripts/build-app.sh
```

При первом запуске скрипт собирает компактный FFmpeg 9.0.2 из официального архива с закреплённым SHA-256; затем выполняет release-сборку SwiftPM, упаковывает основной процесс, RenamorphWorker, FFmpeg/ffprobe и все их несистемные dylib. Ссылки на библиотеки переписываются относительно .app; затем применяется и проверяется локальная ad-hoc подпись. Homebrew нужен для сборки, готовое приложение содержит медиадвижок. Реестр библиотек, версии, хеши и файлы лицензий находятся в `Contents/Resources/ThirdParty`. Серверы и ключи не требуются. Требуются инструменты разработчика macOS со Swift 6 и Swift Testing; фактически использованы Command Line Tools со Swift 6.4 и SDK 27.0. Для сборки приложения исходники объявляют Swift tools 5.9.

Проверенная конфигурация: **macOS 27.0 (26A428), arm64, внутренний APFS**. Swift-ядро сохраняет deployment target 14.0, но **эта готовая сборка требует macOS 27.0**, поскольку установленные библиотеки FFmpeg собраны для этой ОС. Скрипт вычисляет минимум по всем включённым Mach-O и записывает его в Info.plist. macOS 14–26 и Intel не проверены; текущая .app для них не заявляется. Сборка локальная, не нотарифицированная, распространяется как предварительный выпуск с ad-hoc подписью. `dist` и `.build` — воспроизводимые локальные артефакты.

Проверки:

```bash
./scripts/test.sh
```

Скрипт собирает настоящие движки и запускает Swift Testing. Для используемого CLT явно подключает имеющийся плагин макросов Testing: он нужен для корректной загрузки макросов этой версии CLT. XCTest не требуется. Тестовый RenamorphRecoveryProbe собирается отдельно и **не входит в .app**; он предназначен для SIGKILL, тайм-аутов и проверки отмены дерева процессов. Тесты используют только создаваемые ими каталоги внутри `test-artifacts`.

## Использование

1. Откройте Renamorph и выберите папку через «Выбрать папку…». Существующие несовпадения расширений не преобразуются при первом сканировании.
2. Переименуйте поддерживаемый файл, например `photo.heic` в `photo.jpg`, через Finder, терминал или другую программу.
3. В «Заданиях» откройте подробности: фактический формат, SHA-256 одобряемой версии, параметры и потери. Нажмите «Преобразовать» либо «Отклонить».
4. На экране настроек можно задать автоматический режим, запрет или подтверждение для отдельных пар. Правило пары приоритетнее общего режима. Дубликаты правил блокируются интерфейсом и проверяются ядром.
5. В истории доступны Undo, сведения о доступности резерва и «Сохранить оригинал рядом». Последняя команда создаёт новую копию с уникальным именем и не меняет существующие результаты.

Закрытие окна оставляет приложение в строке меню. Меню даёт доступ к окну, паузе наблюдения и завершению. Автозапуск при входе не настраивается приложением; при необходимости пользователь может добавить .app в системные объекты входа.

Настройки, история и резервы находятся в `~/Library/Application Support/Renamorph`. Для полностью отдельного тестового экземпляра:

```bash
open -n dist/Renamorph.app --args --data-dir "$PWD/test-artifacts/manual/State"
```

Одно хранилище может использовать только один процесс. При повреждённом или неизвестном журнале приложение прекращает запуск с диагностикой, не подменяя журнал пустым.

## Фактический охват

Версия 0.4 содержит 29 форматов и 264 направления: 49 растровых, 213 аудио/видео, 2 текстовых. Добавлены AVIF, кодирование HEIC, CAF, WavPack и выбор AAC/ALAC для M4A. Все направления имеют ограничения и проверку результата.

| Вход | Выходы |
| --- | --- |
| JPEG, PNG, TIFF, HEIC/HEIF, BMP, WebP, GIF, AVIF — один кадр | JPEG, PNG, TIFF, HEIC, BMP, WebP, AVIF |
| MP3, WAV, FLAC, AIFF, M4A, AAC, Ogg Vorbis, Opus, WMA, CAF, WavPack | MP3, WAV, FLAC, AIFF, M4A, AAC, Ogg Vorbis, Opus, CAF, WavPack |
| MP4, MOV, MKV, WebM, AVI, MPEG, WMV, TS | MP4, MOV, MKV, WebM, AVI и перечисленные аудиоформаты |
| SRT, WebVTT | SRT ↔ WebVTT |

Исключение: WMV → AVI отключено из-за изменения временных меток; для WMV доступны остальные видеоцели.

Подробности, реальные выходные кодеки и потери: [матрица и ограничения](FORMATS.md).

Примеры: `song.flac` → `song.mp3`, `clip.mov` → `clip.mp4`, `clip.mp4` → `clip.mp3` (извлечение звука), `captions.srt` → `captions.vtt`. В настройках доступны режим перепаковки/перекодирования, битрейт и частота аудио, качество видео и кодек M4A при перекодировании. Эффективные параметры, операция и версия движка сохраняются в истории. Совместимые расширения, исправление неверного расширения и изменение основной части имени не меняют байты. Например `.opus` → `.ogg` уже соответствует контейнеру Ogg.

Группы `song.mp3,flac` и `photo.png,webp` реально создают независимые результаты из одного оригинала. Повторяющиеся форматы объединяются, совместимые ветки копируются побайтово, неизвестное расширение блокирует запрос целиком.

Политика группы по умолчанию **не согласована**: подготовка возможна, публикация ожидает выбора пользователя. В настройках доступен вариант «Подготовить всю группу, затем публиковать». Он разрешает последовательную журналируемую публикацию только после подготовки всех активных веток. **Публикация нескольких файлов не атомарна.** Ошибка или сбой в середине переводит операцию в восстановление; это не обычный частичный успех. До публикации можно отменить отдельные ветки. Во время публикации отмена откладывается до сохранения восстановимого состояния.

## Сохранность данных

- Источник фиксируется по идентичности файла, размеру, временам изменения и SHA-256. Подтверждение относится к этой версии. Повторное переименование, замена или правка блокируют устаревшее задание.
- Резерв создаётся эксклюзивно, синхронизируется и проверяется; движок пишет только временный результат. Проверки результата выполняет новый процесс инспектора: проверки соответствующего семейства, включая медиапотоки/длительность/кадры и текст/тайм-коды субтитров.
- Рабочая область находится рядом с источником: `.renamorph-work-<UUID>`. Перед изменением пользовательских путей журнал синхронизируется на диск.
- Для занятого источником пути используется APFS-замена `RENAME_SWAP`: прежний объект остаётся в рабочей области. Для нового пути используется `RENAME_EXCL`: существующий объект не перезаписывается.
- После swap проверяется идентичность и хеш вытесненного файла. При гонке сохраняются резерв, вытесненная версия и результат; операция требует сверки. Гарантия не подразумевает блокирование сторонних программ, которые пишут через уже открытый дескриптор.
- Undo сначала проверяет все опубликованные версии и прежнее имя. Чужая правка, замена или занятое имя дают конфликт. Восстановление также журналируется. Нет обратного кодирования.
- После аварийного завершения публикация/Undo помечаются «Требуется восстановление», без автоматического удаления или отката. Откройте рабочую папку, используйте «Сохранить оригинал рядом» и сверьте результаты. Автоматическое продолжение частично опубликованной группы не реализовано.
- Если прежняя папка уже перемещена или удалена, извлечение оригинала создаёт копию в `Recovered` внутри хранилища приложения. История сохраняет исходные пути; автоматического переписывания старых записей под новые пути нет.
- Автоматического удаления старых оригиналов нет. При лимите резервов операция останавливается до публикации. По умолчанию выделено 2 ГБ, лимит настраивается. Рабочие данные завершённых/прерванных публикаций сохраняются отдельно и не входят в этот лимит; они могут требовать дополнительного места. Это сознательный приоритет сохранности вытесненных версий.
- При отмене или ошибке до начала публикации удаляются только временные результаты этой операции; источник и уже созданный резерв сохраняются. Данные начавшейся публикации не очищаются автоматически.

Один конвертер работает одновременно. Новые настройки по умолчанию: вход до 2 ГБ, 40 Мп, тайм-аут 900 с; лимит входа и тайм-аут доступны в интерфейсе. Ранее сохранённые значения (например, 128 МБ/120 с) сохраняются при обновлении. FFmpeg использует до четырёх потоков кодирования/декодирования в зависимости от числа CPU, лимит отдельного выделения памяти и размера кадра; размер результата ограничен в процессе. Перед подготовкой проверяется свободное место для исходника и оценочного бюджета каждой ветки. Выход, превысивший бюджет, даёт ошибку с сохранением оригинала. Это параметры реализации, а не требования оригинального Consul. Прогресс показывает этапы и готовые ветки; точный процент кодека пока не передаётся в интерфейс.

## Области доступа и ограничения

Наблюдение использует FSEvents, снимок идентичностей файлов и стабилизацию событий. Раз в 30 секунд и при сигнале о потере событий/смене корня выполняется безопасная сверка, не запускающая конверсии. Переезд корня восстанавливается через bookmark, если он разрешается. Иначе интерфейс показывает проблему доступа. При старте старые события не воспроизводятся как новые намерения.

Поддерживается только внутренний локальный APFS. Симлинки и пути через них, hard links, dataless placeholders, iCloud/File Provider, внешние и сетевые тома отклоняются. Скрытые файлы и пакеты исключены из наблюдения. Рескан больших деревьев может быть дорогим; в этой версии события вызывают сверку выбранных деревьев, а не инкрементальную базу всех каталогов.

Приложение не запрашивает Full Disk Access. Доступ к выбранным папкам зависит от обычных прав и TCC macOS. Проверяются чтение, рабочая область, резерв и публикация. Тесты не дают одинаковых гарантий для любых файловых систем или отключения питания.

Все операции выполняются локально. Передачи содержимого файлов внешним сервисам нет. Вызовы FFmpeg ограничены локальным дескриптором входа; встроенные сетевые возможности самого FFmpeg не используются. Лицензирования приложения, trial и автообновлений нет. Отдельный процесс изолирует сбой конвертера, **не является песочницей** и не доказательство сетевой изоляции средствами ОС.

## Открытые продуктовые решения

Ответа на уточнение обязательной матрицы первой версии, общей политики групп и необходимости лицензирования/trial/обновлений в ходе реализации не было. Расширенный набор аудио/видео/растров/субтитров выбран по запросу пользователя «наполни форматами для аудио, видео и тп»; это рабочий охват, не утверждённая замена всех 115 форматов Consul. Групповая политика выбирается явно в приложении. Коммерческий и обновляющий контуры отсутствуют, а не считаются согласованно ненужными.

## Выпуск 0.4

Иконка macOS включена в .app и проверена в Finder. Размер пакета: 31.4 MiB выделенного места вместо 93.6 MiB в 0.2. Замеры на контрольных файлах: полная проверка медиа примерно в 6 раз быстрее, H.264 перекодирование с проверкой — в 3.4 раза. Это локальные медианы, не обещание одинакового ускорения для всех файлов. [Отчёт, данные и ограничения](VALIDATION.md). Архив для переноса: `dist/Renamorph-0.4.1-macOS-arm64.zip`; checksum — рядом.

Исходная иконка и воспроизводимая упаковка: `assets/AppIcon.png`, `assets/AppIcon.icns`, `assets/icon-generation.json`, `scripts/build-icon.sh`. Сборочный кэш движка находится в `~/.cache/Renamorph`, ссылка `.build/media` ведёт к нему. Исходники FFmpeg и проверенный архив находятся в `.build/vendor`; эти данные не входят в готовую .app. Для явного альтернативного движка можно задать `RENAMORPH_MEDIA_BIN`, после чего необходимо повторить матрицу проверок.
