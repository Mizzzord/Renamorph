# Инженерные заметки

## План выпуска 0.3 (30.09.2026)

Работа по поручению пользователя в режиме «к цели»: исходные замеры и сохранённая сборка 0.2; генерация и упаковка иконки; компактный FFmpeg с сохранением текущей матрицы; сокращение повторного анализа и ограниченный параллелизм; оценка дополнительных форматов; реальные проверки движка, транзакций, интерфейса и Finder; выпуск и отчёт. Транзакционные гарантии и полнота проверки результата не сокращаются. Целевая проверяемая среда — этот Mac, arm64/macOS 27/APFS; другие ОС и файловые системы не считаются проверенными.

## Состав

- `RenamorphApp`: AppKit lifecycle, NSStatusItem, SwiftUI-окно; состояние интерфейса публикуется в main queue.
- `FolderWatcher`: отдельная очередь FSEvents, debounce, сопоставление `(volume, inode, birth time)`, проверка стабильности stat, исключения, начальный/периодический рескан. Восстановление снимка всегда без запуска заданий.
- `Coordinator`: последовательная очередь заданий; сериализует публикации, хранит эффективные правила и версии входа. Отмена передаётся через отдельный потокобезопасный токен и не ждёт освобождения очереди UI.
- `StateStore`: атомарно заменяемый JSON, `fsync`/`F_FULLFSYNC`, эксклюзивная блокировка экземпляра. Схема 1. Неизвестная схема/ошибка декодирования блокирует запуск. История не удаляется автоматически.
- `SafeFiles`: lstat/open с O_NOFOLLOW, SHA-256, стабильное копирование, проверки APFS/доступа, `RENAME_SWAP` и `RENAME_EXCL`, синхронизация файлов/каталогов.
- `Transaction`: резерв, независимая подготовка веток, валидация, журналирование и публикация, Undo, извлечение оригинала при конфликте.
- `RenamorphWorker`: один запрос/ответ JSON в закрытом временном IPC-каталоге. Аргументы передаются через `Process.arguments`, shell не используется. Worker не выполняет публикацию. ImageIO работает внутри worker; FFmpeg/ffprobe запускаются через posix_spawn с отдельными аргументами и наследуют его process group. Исходник передаётся открытым дескриптором stdin через протокол fd, без расширения и без разрешения внешних ресурсов. Вывод дочерних инструментов находится в IPC-каталоге, который координатор удаляет после завершения/отмены. Отмена уничтожает его process group; исчезновение родителя отслеживается самим worker.

## Граница публикации

`approvedVersion == source` и повторная проверка source перед подготовкой и перед публикацией обязательны. Копия дополнительно проверяется по хешу и стабильности источника. Резерв никогда не является выходом кодировщика. Все результаты проверяются перед первой сменой пользовательского пути.

Перед каждым шагом сохраняются целевые и временные пути, ожидаемые хеши/идентичности и состояние. После `RENAME_SWAP` старый объект остаётся по staging-пути. Если его версия не соответствует одобренному источнику, автоматическая обработка останавливается с `needsRecovery`, сохраняя все доступные версии. При новой цели `RENAME_EXCL` не заменяет существующее имя. Публикация группы последовательна, не является общей атомарной операцией и не откатывается автоматически поверх возможных новых пользовательских правок.

После успеха сохраняются рабочие каталоги, содержащие вытесненные оригиналы/результаты Undo. Они полезны при записи стороннего приложения через открытый дескриптор после переименования. Их нельзя считать обычным временным мусором. Временные результаты отменённых операций до публикации очищаются отдельно.

При старте состояния публикации/восстановления становятся `needsRecovery`. Прерванная подготовка становится отменённой, с сохранёнными данными. Подтверждения ожидающих задач повторно проверяют сохранённую версию; очередь не продолжает устаревшие задания вслепую.

## Восстановление

Обычный Undo требует доступный резерв, совпадение SHA-256 резерва, точное совпадение всех опубликованных версий и свободное прежнее имя (кроме собственного результата). Затем оригинал создаётся отдельно, переносится эксклюзивно или меняется местами с собственным результатом. Удаляемые с пользовательских путей результаты перемещаются в рабочую область и проверяются после переноса. Конкурентное изменение остаётся сохранённым и требует сверки.

При `needsRecovery` или конфликте «Сохранить оригинал рядом» создаёт новую проверенную копию с уникальным именем. Это безопасное извлечение оригинала, а не автоматическое завершение/отмена частичной публикации. Статус конфликта остаётся видимым, пока пользователь разбирает результаты. Удаление рабочих каталогов и автоматическое продолжение частичной группы в этой версии не предусмотрены.

## Проверенные источники API

API проверены по установленному Apple SDK и первичной документации: [FSEvents и file-level events](https://developer.apple.com/documentation/coreservices/kfseventstreamcreateflagfileevents), [ImageIO sources](https://developer.apple.com/documentation/imageio/cgimagesourcecreatewithurl(_:_:)), [ImageIO destinations](https://developer.apple.com/documentation/imageio/cgimagedestination). Наличие этих API в нашей реализации не приписывается оригинальному Consul.

## Известные ограничения

Периодический рескан безопасно пропускает неподтверждённые изменения, случившиеся во время разрыва наблюдения, вместо массовой конвертации. Полного долговременного журнала всех переименований нет. Большие деревья сканируются полностью. Сетевые и внешние тома отвергаются. Полного сохранения ACL, xattrs, Finder tags и всех исходных атрибутов результата не заявлено: сохраняются исходные байты в резерве и POSIX mode результата. Undo возвращает байты, а не полную метадатную копию файловой системы. Одновременная запись сторонних приложений может потребовать ручного восстановления; файловые объекты не блокируются средствами обязательной блокировки ОС.

## Расширение форматов 0.2

`FileFormat` заменяет ограниченный enum `ImageFormat`, сохраняя строковые значения старых форматов в JSON. `ContentInfo` добавляет опциональные медиапотоки, временные метки и семантический хеш субтитров. Новые параметры `ConversionOptions` декодируются с безопасными значениями по умолчанию; прежние настройки и история сохраняются. Медиаплан выбирается по фактическим кодекам и настройкам до подтверждения, его операция/версия движка сохраняются в истории. Отдельное состояние распознавания показывает длительный анализ и позволяет его отменить.

FFmpeg ограничен числом вычислительных потоков `min(4, max(1, activeProcessorCount / 2))`, max_pixels и max_alloc; filter_threads=2, filter_complex_threads=1. Очередь запускает одно задание одновременно; worker ограничивает размер создаваемого файла и время жизни. Это ресурсные ограничения, не песочница. Ошибка декодера или лимита не публикует результат. Бюджет медиа-результата — максимум из четырёх размеров входа, двойного PCM-представления и 64 МБ. Бюджет проверяется на диске до резервирования и задаёт RLIMIT_FSIZE. При сложном видео оценка может оказаться недостаточной: операция завершится безопасной ошибкой, без расширения лимита постфактум.

`scripts/build-media.sh` собирает компактный FFmpeg из официального архива с закреплённым SHA-256 в каталоге кэша без пробелов (ограничение Makefile FFmpeg). `scripts/bundle-media.py` копирует готовый движок, рекурсивно включает несистемные dylib, переписывает ссылки в @loader_path и подписывает все Mach-O. В `ThirdParty/manifest.json` находятся версии/хеши/формулы. Минимальная ОС .app вычисляется по LC_BUILD_VERSION включённых файлов; текущий комплект требует 27.0, несмотря на deployment target Swift-ядра 14.0. Это локальная сборка, не подготовленный комплект для публичного распространения.

## Оптимизация и упаковка 0.3

Иконка сгенерирована встроенным image_gen; точный prompt в `assets/icon-generation.json`. PNG-мастер 1024×1024 с alpha преобразуется `sips` и `iconutil` в десять представлений 16…1024 px. CFBundleIconFile, категория Utilities, PkgInfo и About-панель подключены до подписи.

FFmpeg 9.0.2 закреплён SHA-256; подпись архива вручную сверена с официальным release key FCF986EA15E6E293A5644F10B4322F04D67658D8. Автоопределение необязательных библиотек, сеть, ffplay, устройства, документация и debug-символы отключены. Native-кодеки/демультиплексоры/фильтры, zlib/bzlib и необходимые внешние кодеки сохранены; удаляются зависимости OCR, shaderc/placebo, x265 и другие неиспользуемые движки. HEVC остаётся доступен через native-декодер, AV1 — через dav1d. SIMD/NEON не отключены.

При упаковке сохраняется реестр кодировщиков/декодировщиков и версия движка, связанный с SHA-256 ffmpeg/ffprobe. Worker проверяет хеши, затем использует реестр без повторных запусков -encoders/-decoders/-version. Для внешнего комплекта без реестра остаётся фактическая проверка кодеков.

Анализ сначала проверяет контейнер, параметры и ограничения; затем ffprobe полностью декодирует все принятые потоки за один проход. Audio frames обязаны содержать samples, video frames — строгие монотонные PTS. Любое сообщение уровня error отвергает результат, даже если ffprobe вернул 0. Вывод обрабатывается через pipe, без большой таблицы на диске. Хеши источника/резерва/выхода, повторные проверки версии и durable-журнал публикации сохранены.

CAF и WavPack используют имеющиеся native-кодеки. M4A получает опцию ALAC; старый JSON декодируется с AAC. HEIC и AVIF кодируются ImageIO и доступны только при наличии системного кодировщика. Доступность показана в реестре маршрутов и интерфейсе. WavPack получает явный размер блока, чтобы короткий первый декодированный MP3 frame не ломал инициализацию кодировщика.
