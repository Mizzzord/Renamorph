# Отчёт проверки ConsulMAC 0.1.0

Дата: 16 сентября 2026 года. Проверки выполнены на специально созданных синтетических файлах и копиях внутри `test-artifacts`; пользовательские изображения не использовались.

## Среда и артефакт

- macOS 27.0, build 26A428; архитектура arm64.
- Swift 6.4, Command Line Tools, SDK macOS 27.0.
- Внутренний SSD, APFS, `/System/Volumes/Data`, протокол Apple Fabric. Проверки успешных транзакций относятся только к этому тому.
- Выпускная сборка `dist/ConsulMAC.app`, основной процесс и отдельный helper `Contents/Helpers/ConsulWorker`.
- Обе программы — Mach-O arm64. Сборка связана только с системными framework-библиотеками, сторонние конвертеры не устанавливались.
- `codesign --verify --deep --strict dist/ConsulMAC.app` завершился успешно. Подпись ad-hoc; нотарификация не выполнялась.
- Deployment target 14.0 установлен при создании проекта. Он не является результатом проверки на macOS 14.

## Автоматические проверки

Команда: `./scripts/test.sh`. Итог последнего полного запуска: **34 теста, 0 ошибок, 10,710 с**. Проверены реальные бинарники ConsulWorker и файловые операции на APFS. [Полный журнал](validation/tests.log).

| Группа | Фактическое подтверждение |
| --- | --- |
| Матрица направлений | Все 12 объявленных направлений ImageIO; входы имеют намеренно неверные расширения; выход проверяется повторным инспектором |
| Основной сценарий | HEIC → JPEG по переименованию; проверка содержимого; резерв; Undo с точным совпадением SHA-256 |
| Совместимость и намерение | Альтернативные расширения, смена basename, опциональность новых файлов на уровне нормализатора |
| Правила | Приоритет пары над общими настройками, блокирование дубликатов; автоматический HEIC → JPEG через настоящий FSEvents и Coordinator |
| Версия входа | Правка до подготовки, правка после подготовки, замена файла теми же байтами: устаревшая операция отвергается |
| Группы | Все ветки из одного резерва; исходный формат копируется побайтово; повторные/неизвестные расширения; отмена ветки; несогласованная политика останавливает публикацию |
| Конфликт цели | Занятое имя другой ветки сохраняет чужие байты и исходник, ни одна ветка не публикуется |
| Резервы | Исчерпание заданной квоты останавливает операцию; оригинал сохраняется; отсутствие резерва блокирует Undo |
| Отмена | Отмена до подготовки; очистка только неопубликованных результатов; остановка тестового зависшего процесса вместе с настоящим дочерним процессом |
| Движок | Отсутствующий helper, ненулевой код/нет ответа, тайм-аут; заведомо некорректные размеры в JSON-ответе отвергаются до арифметики |
| Повреждённые/неподходящие данные | Повреждённый JPEG, многостраничный TIFF, превышение лимита пикселей; альфа → JPEG требует явного выбора фона |
| Свойства растра | Ориентация 6 физически применяется к пикселям, ширина/высота меняются местами; выходная ориентация 1 |
| Права/ссылки | Реальное ограничение POSIX-записи в тестовый каталог; симлинки и hard links отвергаются |
| Undo-конфликты | Ручная правка результата, занятое прежнее имя, удалённый резерв: чужие данные сохраняются |
| Журнал | Сохранение и чтение настроек/версий/заданий; второй экземпляр не получает блокировку того же хранилища |
| Наблюдатель | Реальные файловые переименования; исключённая папка; быстрые последовательные переименования; рескан без повторного запроса |
| Восстановление | Инъекция остановки после swap/первой ветки, сохранность исходника/резерва/частичного результата; реальный SIGKILL тестового координатора после swap; следующий Coordinator помечает журнал `needsRecovery` |
| Перемещённая папка | Извлечение резерва в `Recovered`, когда первоначальный каталог больше не существует; опубликованный результат не меняется |

ConsulRecoveryProbe используется только для аварийных и процессных сценариев. Это настоящий отдельный процесс с реальными POSIX-операциями, но его «зависший движок» — специально созданный тестовый процесс, не ошибка ImageIO. Часть аварийных границ проверяется инъекцией исключения; отдельный тест действительно посылает SIGKILL себе после `RENAME_SWAP`.

## Пройденные сценарии интерфейса

Приложение реально запускалось как .app. Через native UI были выполнены:

1. Проверка пустого состояния и выбор отдельной папки в NSOpenPanel.
2. Переименование синтетического `photo.heic` в `photo.jpg` командой файловой системы. В окне появилась карточка «Ожидает решения», источник HEIC, цель JPEG, 640×480, версия SHA-256 и эффективные параметры.
3. Подтверждение кнопкой «Преобразовать». Карточка перешла в «Готово». Независимая команда `file` определила настоящий JPEG 640×480, baseline, 8-bit.
4. «Восстановить оригинал». Файл HEIC вернулся под прежним именем, проверка SHA-256 дала `OK`.
5. Создание в настройках автоматического правила HEIC → JPEG. Повторное переименование завершилось без запроса; история содержит отдельную успешную операцию.
6. Добавление тестовой ручной правки к JPEG и попытка Undo. Интерфейс показал «Конфликт восстановления»; SHA-256 изменённого файла после попытки совпал с его хешем до попытки.
7. Перемещение наблюдаемого корня. В интерфейсе «Папки» и сохранённых настройках появился новый путь `WatchedRenamed`; число операций осталось равным двум.
8. Перезапуск с тем же тестовым хранилищем. История, конфликт, выбранная папка и правило сохранились; старые несовпадения не создали новых заданий.
9. В выпускной сборке извлечён оригинал после перемещения папки. Создан файл в `State/Recovered`; его SHA-256 совпал с исходным HEIC: `61d5026b01a72a8ffc4f322f4fc612b9599c1501cda1cb857b880133a29c40d3`.
10. Проверены экраны заданий, папок, настроек и истории; работает завершение Command-Q. Приложение использует NSStatusItem и LSUIElement. Длительная конвертация с параллельным взаимодействием с окном отдельно не воспроизводилась; worker запускается в фоновой очереди координатора.

Визуально проверялось стандартное окно на доступном экране. Попытка изменить его размер через инструмент не подтвердила изменение геометрии; тест разных размеров/масштабов экрана не засчитывается как выполненный. Разрыв из-за блокировки экрана завершён после разблокировки пользователем, визуальная проверка продолжена.

## Ограничения доказательств

- **Не заполнялся физический диск до ENOSPC.** Проверены квота резерва и отказ в записи по POSIX; проверки свободного места и ошибки записи реализованы, но фактическое исчерпание целевого/резервного тома не воспроизведено.
- **Не проверялось отключение питания** и поведение накопителя при потере питания. SIGKILL проверяет падение процесса, а не надёжность аппаратного кэша.
- Внешние диски, NAS, SMB/NFS, HFS+/FAT/exFAT и облачные провайдеры не проверены как успешные маршруты и не поддерживаются этой сборкой. Реальные облачные placeholders отдельно не создавались.
- TCC-отказ/отзыв разрешения в настройках macOS не воспроизводился; реальный POSIX-отказ проверен.
- События kernel/user dropped не вызывались принудительно. Безопасный ручной рескан, запуск и перемещение корня проверены; ветка dropped использует тот же режим восстановления снимка.
- Не проводилась нагрузочная проверка миллионов файлов, исчерпания памяти, всех вариантов EXIF/ICC/HDR, визуального качества широкой коллекции изображений или неблагоприятных гонок на уровне отдельных системных вызовов.
- Контроль сети средствами packet capture не выполнялся. В коде нет сетевых клиентов, внешних движков и передачи файлов; отдельный worker не объявляется sandbox.
- Проверка разных масштабов экрана, VoiceOver, macOS 14–26 и Intel остаётся невыполненной.
- Полного сохранения ACL/xattrs/Finder tags не заявлено. Резерв и Undo гарантируются на уровне проверенных исходных байтов; рабочие вытесненные объекты сохраняются для дополнительной сверки.
- Частично опубликованная группа не откатывается и не продолжается автоматически. Интерфейс сохраняет состояние восстановления и позволяет извлечь оригинал в новый файл.
- Обязательная продуктовая матрица, политика групп по умолчанию, лицензирование, trial и обновления не согласованы ответом пользователя. Их отсутствие/блокировка не выдаётся за реализацию всей модели Consul.

## Сборочные особенности

Первая попытка с XCTest не собралась: XCTest отсутствует в установленном CLT. Тесты переведены на имеющийся Swift Testing. Новый макрос `@State` SDK 27 требовал отсутствующий SwiftUI macro plugin; интерфейс использует явный alias стандартного property wrapper `SwiftUI.State<Value>`. Это не отключает проверки типов и совместимо с фактически выполненной сборкой SDK 27.

SwiftPM/CLT выводит предупреждения о несуществующих дополнительных путях поиска `/Library/Developer/CommandLineTools/Developer/...`; требуемые системные frameworks разрешаются, сборка, запуск и тесты завершены успешно. [Журнал release-сборки](validation/release-build.log).
